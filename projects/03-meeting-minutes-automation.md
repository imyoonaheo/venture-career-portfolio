# 03 · Meeting Minutes Automation

**Voice Workflow · AI Summary · Structured DOCX · Slack Integration**

## 문제 정의

기업 미팅 이후 음성 기록을 다시 듣고 회의록을 작성한 다음, 결정사항과 후속 할 일을 담당 채널에 공유하는 일은 시간이 많이 들고 누락이 생기기 쉽습니다. 이를 개선하기 위해 **음성 기록을 요약·분류하는 흐름**과 **정리된 회의 내용을 Word 파일로 만들고 Slack에 공유하는 흐름**을 연계했습니다.

## Workflow — Voice Transcriber 우선 전사 후 채널별 분류·게시

![Voice Transcriber-first automation workflow — fictional data](../assets/meeting-automation-workflow.svg)

*가상 데이터로 작성한 개념 이미지입니다. 실제 Slack 화면이나 DOCX 파일 첨부 성공 화면이 아닙니다.*

![회의 음성 자동화 예시 — 시각화된 데모 화면](../assets/meeting-automation-example.png)

*Figure 2. 회의 음성 입력부터 전사·요약 및 후속 업무 분류, Word 문서화를 보여주는 **설명용 예시 이미지**입니다. 실제 Slack 실행 화면이 아니며, 이미지에 표현된 Word 파일 공유 성공은 검증된 운영 결과를 의미하지 않습니다. 실제 제공된 Slack 화면에서는 파일 업로드 권한 오류로 텍스트 대체 게시가 이루어졌습니다.*

```mermaid
flowchart TD
    A["Slack에 회의 음성 파일 업로드"] --> B["Voice Transcriber가 음성을 텍스트로 전사"]
    B --> C["전사 결과 분석 · 회의록 요약 및 후속 할 일 추출"]
    C --> D["회의록용 Slack 채널에 회의 요약 게시"]
    C --> E["업무관리용 Slack 채널에 후속 할 일 게시"]
    C -. "별도 문서화 흐름" .-> F["회의 정보를 구조화된 JSON으로 준비"]
    F --> G["Word 회의록 DOCX 생성"]
    G --> H{"Slack 파일 업로드 권한 정상?"}
    H -->|"정상인 경우 · 구현된 경로"| I["Word 파일 첨부"]
    H -->|"권한 누락 · 제공된 화면에서 확인"| J["파일 첨부 실패 안내 · 회의록 텍스트 대체 게시"]
```

*Figure 1. Voice Transcriber가 Slack 음성을 **먼저 전사**한 다음 내용을 분류해 회의록·후속 할 일을 **서로 다른 업무 채널에 전달**하는 흐름. 점선은 별도로 구현된 DOCX 문서화 경로이며, Word 파일의 Slack 첨부 성공을 의미하지 않습니다.*

**확인된 작업 순서:** 음성 등록 → Voice Transcriber 전사 → 요약·할 일 추출 → 목적에 맞는 Slack 채널로 분리 게시. DOCX 생성·전송 기능은 **별도 자동화 구성요소**입니다. 실제 공유된 Slack 화면에서는 Word 파일 업로드가 `missing_scope: files:write` 오류로 실패한 뒤 **회의록 텍스트가 대체 게시**되었습니다.

## 확인된 화면과 구현 근거

| 단계 | 확인 내용 | 확인 범위 |
|---|---|---|
| 음성 파일 입력 | Slack에 약 48분 분량의 테스트 녹음 게시 | 제공된 화면 |
| Voice Transcriber 결과 | 음성 전사 후 회의록·후속 할 일을 추출하여 목적에 맞는 서로 다른 Slack 채널에 게시 | 제공된 Slack 화면과 사용자 설명 |
| DOCX 자동 생성 | JSON을 받아 Word 양식의 OOXML을 수정하는 스크립트 | 제공된 소스 및 예제 생성 시험 |
| Slack 파일 첨부 | 봇의 메시지·파일 업로드 로직 | 스크립트 구현 확인. 실제 화면에서는 `files:write` 권한 누락으로 업로드 실패 |
| 오류 시 대체 게시 | DOCX 첨부가 불가능한 경우 회의록 본문을 텍스트로 게시 | 제공된 Slack 화면 |

## 사용 기술

- **Python 3, JSON, OOXML/DOCX:** 회의 메타데이터와 주요 항목을 Word 파일로 변환
- **Bash, curl, Slack Web API:** Slack 메시지·스레드 게시 및 문서 첨부 연동
- **Voice Transcriber:** 먼저 음성을 전사한 후 내용을 요약·분류하고 회의록 및 후속 할 일을 각 Slack 채널로 게시하는 별도 루틴. DOCX 생성 스크립트와 구분

## Demo Scenario — fictional data

실제 업무 데이터 대신 **가상의 프로젝트 회의**를 사례로 구성하면 입력과 출력의 관계를 안전하게 설명할 수 있습니다.

| 단계 | 가상 데모 내용 |
|---|---|
| 입력 | '샘플 프로젝트 진행 회의' 녹음 파일 |
| 회의록 | 진행 현황, 주요 논의사항, 결정사항 |
| 후속 업무 | '문서 초안 보완' · '다음 회의 일정 확인' |
| 공유 | Voice Transcriber가 회의록·할 일을 각 채널로 나누어 게시하고, Word 문서는 별도 생성 결과를 확인 |

실제 Slack 캡처에는 업무상 기업·투자 논의, 날짜·기한, 채널 및 담당자 정보가 포함되어 있으므로 원본 이미지는 게시하지 않습니다. 가상 데이터로 재현한 화면에 **“DEMO · 가상 데이터”** 표시를 추가하고 회사 승인 범위를 확인한 뒤 공개용 캡처를 등록하는 방식이 적절합니다.

## 검증 범위 및 한계

- 제공된 원본 ZIP의 문서 생성·공유 스크립트 및 입력 구조를 검토했습니다.
- 예제 입력을 사용한 DOCX 생성 시험에서 문서 및 주요 섹션 입력을 확인했습니다.
- 실제 Slack 화면에서는 **자동 회의록 및 후속 할 일 텍스트 게시**가 확인됩니다.
- 동일 화면에서 **Word 파일의 Slack 업로드는 실패**했습니다(`missing_scope: files:write`). 해당 화면을 성공 사례로 사용하지 않습니다.
- 전체 전사 루틴의 신뢰도, Slack 파일 업로드 성공률, 절감 시간 등 정량적 운영 성과는 별도 검증하지 않았습니다.

**공개 범위:** 회사 원본 코드·Word 양식·실제 회의 내용·인증정보·Slack 채널 식별자는 공개하지 않습니다.

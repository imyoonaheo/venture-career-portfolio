# 03 · Venture Operations ERP

**Internal Tool · Data Structure · Workflow Design**

## 업무 문제

AC·VC 업무에서는 기업별 기본정보, 보육 단계, 미팅 기록, 투자사 접촉 이력, 요청 자료, 후속 일정이 동시에 발생합니다. 정보가 여러 문서와 커뮤니케이션 도구에 분산되면 담당자가 현재 상태와 다음 행동을 연결하기 어려워집니다.

이 문제를 해결하기 위해 **기업 중심의 정보 및 업무 관리 체계**를 구상하고 내부 ERP 설계·개발·개선에 참여했습니다.

## 원본 코드에서 확인된 기능 영역

| 구분 | 구현 근거가 확인된 영역 |
|---|---|
| 기업·프로젝트 관리 | 기업 상세 정보, 단계·담당자·자료·후속관리 |
| 투자연계 | 투자사 접촉 이력·진행 상태·담당자 관리, TIPS/LIPS 매칭 항목 |
| 미팅·할 일 | 미팅 등록, AI 기반 회의 요약, 후속 To-do 연결 |
| 기업 접수 및 평가 | 신청 접수, 심사 상태, 데모데이 평가 관련 화면·API |
| 권한·자료 | 관리자·기업 사용자의 접근 구분, 파일 관리 관련 흐름 |
| AI 지원 | 데이터 점검 및 보고, 알림·변경 이력·되돌리기 관련 구조 |

**확인된 기술:** Next.js, React, TypeScript, Supabase, SQL, Google Gemini API. Slack 및 Google Drive 관련 연동 코드도 존재합니다.

## 설계 접근

- 기업이라는 공통 기준으로 자료·미팅·진행 단계·할 일을 연결
- 실제 사용자 동선을 기준으로 기업 상세 페이지와 관리 화면 설계
- 반복 점검과 문서화는 자동화하되, 투자 판단은 담당자가 수행하는 구조 유지
- 데이터 변경의 기록과 되돌리기 등 검토 가능한 운영 방식 고려

## 구현과 운영의 구분

원본 코드에는 투자 딜 관련 일부 목업(mock) 데이터가 포함되어 있고, AI 직원 중 `daily`·`weekly`는 `active`, `voice`·`system`은 `planned`로 분류되어 있습니다. 따라서 **ERP가 실제 투자 집행을 자동화하거나 모든 AI 업무가 정식 가동 중이라고 주장하지 않습니다.**

**검토 범위:** 원본 저장소의 구조 및 대표 기능 파일을 확인했습니다. 전체 파일 전수 검사나 운영 환경 성능 검증은 하지 않았습니다.

**기밀 유지:** 원본 소스코드, 실제 화면 캡처, 기업 DB, 사용자 정보, 인증 설정은 본 포트폴리오에 포함하지 않습니다.

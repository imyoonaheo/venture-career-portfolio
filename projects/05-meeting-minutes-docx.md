# 05 · 회의록 자동 문서화 및 Slack 공유

**Document Generation · Workflow Automation · Slack Integration**

## 프로젝트 개요

기업 미팅 이후 회의 내용을 정리하고, 지정된 양식에 맞춰 회의록을 만들고, 담당 채널에 공유하는 과정은 시간이 들고 담당자마다 형식이 달라질 수 있습니다. 이를 줄이기 위해 **회의 정보를 Word 회의록으로 자동 변환하고 Slack 봇 계정으로 공유하는 업무 흐름**을 구성했습니다.

이 프로젝트는 회사의 음성 메모 자동화 루틴과 **연결되는 문서 생성·공유 단계**입니다. 이 저장소 자체에 음성 인식 엔진이나 전체 전사 워크플로가 포함된 것은 아닙니다.

## 제가 다룬 문제와 접근 방식

- **형식의 일관성:** 정리된 회의 내용을 회사에서 사용하는 고정 양식에 반복 입력해야 하는 작업을 자동화하고자 했습니다.
- **내용의 구조화:** 자유롭게 정리된 기록을 회의 정보와 공통 목차에 맞춰 입력 가능한 데이터 형태로 정의했습니다.
- **공유 과정의 자동화:** 문서 생성 이후 파일 첨부와 채널·스레드 게시를 하나의 실행 흐름에 연결했습니다.
- **자동 게시물의 구분:** 직원 개인 계정이 아니라 전용 Slack 봇이 자동 게시하도록 설계해 메시지 출처를 구분했습니다.

## 코드에서 확인한 구현 내용

| 영역 | 구체적인 구현 |
|---|---|
| 회의록 입력 | JSON에서 제목·일시·참석자·회의 목적·검토자료와 목차별 항목을 읽도록 구성 |
| Word 문서 생성 | 기존 DOCX 템플릿의 OOXML을 수정하여 제목, 표, 6개 주요 섹션을 자동 입력 |
| 문서 가독성 | 논의 주제 소제목과 항목형 문단에 들여쓰기·줄 간격·강조 서식 적용 |
| 파일 출력 | 입력 제목과 날짜를 바탕으로 파일명 구성, 별도 출력 경로 지정 지원 |
| Slack 게시 | Slack Web API를 사용한 텍스트 메시지·스레드 댓글·Word 파일 첨부 흐름 구현 |
| 자동 게시 계정 | 직원 개인 계정과 구분되는 봇 게시 방식, 루틴 실행 환경의 자격 증명 활용 구조 |
| 전달 품질 | Slack용 강조 문법 변환, 링크·미디어 미리보기 방지, 게시 링크 반환 |

**구현상 특징:** 별도 `python-docx` 의존성 없이 Python 표준 라이브러리와 Word 파일의 XML 구조를 이용해 문서를 생성했습니다. Slack 연동은 Bash와 `curl`을 활용한 API 호출 방식으로 작성됐습니다.

## 동작 흐름

```text
음성 메모 루틴의 회의 내용 정리 (별도 시스템)
                ↓
회의 메타데이터와 주요 항목의 구조화 (JSON)
                ↓
회사 양식 기반 DOCX 파일 자동 생성
                ↓
Slack 봇 계정으로 파일 첨부 및 메시지 게시
                ↓
게시 링크 확보 · 후속 공유
```

## 기술과 도구

`Python 3` · `JSON` · `OOXML / DOCX` · `Bash` · `curl` · `Slack Web API`

자동 실행은 **외부 클라우드 음성 메모 루틴**과 연결되는 구조이며, 위의 기술 목록은 제공된 회의록 생성·공유 저장소에서 확인된 구현을 기준으로 작성했습니다.

## 검증 범위

- 저장소의 문서 생성·Slack 게시 스크립트와 입력 데이터 구조를 확인했습니다.
- 제공된 예제 입력으로 Word 문서 생성 스크립트를 **로컬 실행해 정상 파일 생성 및 주요 섹션 입력을 확인**했습니다.
- Slack 실제 전송, 자동 루틴의 운영 가동률, 소요시간 절감 수치 등은 별도 검증하지 않았습니다.
- 코드는 동작 흐름의 구현 근거이며, 프로젝트 전체의 정량적 성과를 단정하지 않습니다.

## 공개 범위

이 문서는 **회사 실무 경험을 설명하는 개인 포트폴리오용 사례 소개**입니다. 회사 소유 코드, 실제 회의록, 원본 Word 양식, 업무상 수치, Slack 채널 정보, 봇 인증정보는 공개하지 않습니다. 회사의 승인 범위를 확인한 후 외부 공개합니다.
